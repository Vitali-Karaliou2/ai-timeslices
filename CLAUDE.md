# TimeSlices-AI — обучающее приложение «История ИИ в тематических срезах»

## Что это
Обучающее приложение: история нейронных сетей и генеративного ИИ как **линейная
последовательность тематических срезов**. Две цели содержания:
- на срезах до 2010-х — раскрыть логику чередования всплесков надежд и разочарований
  (golden ages / winter ages; смещение ожиданий между генеративным и объясняющим ИИ);
- на срезах последних ~15 лет — раскрыть детали решений, сделавших возможной современную
  революцию ИИ.
Попутная линия: обучение текущей практике программирования нейросетей — Python, матричная
алгебра, NumPy и PyTorch, от отдельного нейрона «в лоб» до трансформеров, с возможностью
быстрых экспериментов.

Полное описание замысла: @docs/brief/AI_TimeSlices_Brief_RU.md
Терминология: **трек** (`genai` | `xai`), **тематический срез**, **период** (`golden` | `winter`),
**страница**, **демо**, **трасса** (trace — записанный прогон обучения), **вопросы для
самоконтроля**, **задание**. Используй эти слова в коде и комментариях, не придумывай синонимов.

## Стадия
0→1. Один человек плюс модель. Основной источник последовательности срезов —
A_Brief_History_of_AI_with_Deep_Learning (в контексте проекта на Claude.ai). Ближайшая цель —
трек `genai`; для `xai` — только обзорные страницы winter-периодов. Первый набор срезов —
от нейрона Мак-Каллока–Питтса и однослойного персептрона до многослойного персептрона
и обратного распространения ошибки.

## Стек и команды
- Python 3.11+, FastAPI + Jinja2 (server-side rendering, аналог Razor Pages),
  SQLAlchemy + SQLite (файл `app.db` в корне, в .gitignore), Alembic для миграций.
- NumPy и PyTorch (CPU) — только в генераторах трасс демо и материалах заданий;
  **оболочка их не импортирует**.
- Окружение: `python3 -m venv .venv && source .venv/bin/activate` — в облачной сессии это
  делает хук SessionStart (`scripts/setup_env.sh`); если пакетов нет — выполни
  `bash scripts/setup_env.sh` вручную.
- Зависимости: `pip install -r requirements.txt`; PyTorch (CPU) — отдельно,
  `pip install -r requirements-ml.txt`, только когда он нужен по плану сессии.
  Новые пакеты — только через requirements*.txt и с моего согласия.
- Запуск: `uvicorn app.main:app --reload --port 8000` (http://localhost:8000)
- Тесты: `pytest`
- Миграции: `alembic revision --autogenerate -m "<name>"` затем `alembic upgrade head`
- Валидация содержания: `python3 scripts/validate_content.py <path/to/file.json>`
- Навигация по БД: страница `/admin/db` (read-only инспектор: список таблиц, строки) —
  аналог Object Explorer; локально дополнительно можно открывать `app.db`
  в DB Browser for SQLite.

## Структура репозитория
- `app/` — оболочка (единственное FastAPI-приложение):
  `main.py`, `models.py` (SQLAlchemy), `content.py` (загрузка содержания),
  `templates/` (Jinja2), `static/`.
- `content/` — содержание курса (НЕ код оболочки):
  - `course.json` — упорядоченный список срезов (линейный порядок, без DAG);
  - `slices/<slice-id>/slice.json` — срез: годы, трек, период, упорядоченный список страниц;
  - `slices/<slice-id>/pages/<nn>-<page-id>.md` — страницы (Markdown с front-matter `type`);
  - `slices/<slice-id>/demos/<demo-id>/` — демо: `demo.json`, статическая сборка
    (`index.html`, `player.js`, `trace.json`) и `gen/` — код генерации трассы
    (`numpy/train.py`, позже `torch/train.py`);
  - `slices/<slice-id>/questions.json` — вопросы для самоконтроля с раскрываемыми ответами;
  - `slices/<slice-id>/assignments.json` — задания для самостоятельных экспериментов.
- `tests/` — pytest: приёмочные тесты оболочки (docs/acceptance.md).
- `docs/` — brief, спецификации, приёмочные критерии, записи решений (ADR), планы сессий;
  `docs/workflow/content-workflow.md` — процесс работы над содержанием;
  `docs/deferred/deferred.json` — реестр решений, отложенных автором на будущее.
- `scripts/`, `.claude/` — skills, agents, settings (хуки). Всё в репозитории:
  облачные сессии ничего не берут с локальной машины.

## Жёсткие правила
- Оболочка и демо разделены: демо — самостоятельная статическая папка, встраивается через
  iframe; оболочка читает только `course.json`, `slice.json`, `demo.json` и прочие манифесты.
- Демо проигрывает **заранее насчитанную трассу** (`trace.json`), сгенерированную кодом из
  `gen/`. Живой перезапуск обучения из браузера (через API оболочки) — отдельное решение;
  без ADR не делать (см. docs/decisions/0002-traces-not-live.md).
- Реализации одного демо на NumPy и на PyTorch должны давать **одну и ту же трассу**
  (при одинаковом seed); расхождение — это баг или предмет отдельной страницы.
- **Фактическая достоверность**: любые даты, имена, атрибуции идей («кто ввёл», «в каком
  году», «что из чего следовало») — при малейшем сомнении помечай в тексте и в отчёте
  `ПРОВЕРИТЬ ДАТУ: <что именно>` и спроси меня. Не угадывать. Эпохальная достоверность
  кода здесь НЕ требуется: весь код — современный Python/NumPy/PyTorch.
- Никаких новых зависимостей вне requirements.txt без моего согласия. Разрешено заранее:
  fastapi, uvicorn, jinja2, sqlalchemy, alembic, pydantic, markdown, numpy, torch (CPU),
  pytest, httpx, python-multipart, itsdangerous.
- Любое изменение схемы содержания (docs/spec/content-schema.md) или схемы БД — только
  после моего согласия, с черновиком ADR.
- Тексты, которые видит обучаемый (страницы, вопросы, ответы, задания), — черновики:
  помечай их `ЧЕРНОВИК:` до моего утверждения; пометку снимаю я сам.
- Авторские права: материалы из загруженных книг, статей и транскриптов — только для
  точности; не воспроизводить их текст и иллюстрации.
- Не делать на 0→1: трек `xai` глубже обзорных страниц; исполнение произвольного
  пользовательского кода; аккаунты и роли сложнее одного dev-пользователя; оформление
  сверх читаемого минимума; распределённость и масштаб.

## Границы делегирования
Ты решаешь: структуру кода оболочки, реализацию по спецификации, черновики текстов страниц,
наборы вопросов и заданий, генераторы трасс и плееры демо.
Ты спрашиваешь: состав и порядок срезов; любое утверждение о датах, именах и атрибуциях;
любое изменение схемы содержания или БД; формулировки, которые видит обучаемый;
новые зависимости; всё, что нельзя откатить (удаление, force-push, изменение CI).

## Как работать в сессии
1. Прочитай задачу сессии в `docs/plans/` (файл этой сессии) и `docs/decisions/`.
2. Explore → Plan → Code → Commit. План — коротко, в начале ответа. Не переписывай то,
   что не просили.
3. Коммить и пушь часто, небольшими коммитами, в ветку сессии (не в `main`). PR создавай
   только когда задача сессии завершена и `pytest` зелёный.
4. Перед PR — вызови субагента `code-reviewer`; для текстов срезов — `fact-reviewer`.
5. Если чего-то не хватает (доступ, секрет, инструмент) — скажи, чего именно, и остановись.
   Не подменяй, не мокай, не угадывай.

## Содержание: логические страницы и отложенные решения
- Единица работы над содержанием — логическая страница; версии — файлы
  `<S><P>.v<N>.<English_name>.docx`, ответы автора — `<S><P>.v<N>-to-<N+1>.prompt.docx`
  (подробно — docs/workflow/content-workflow.md).
- Перед началом каждой логической страницы выполни
  `python3 scripts/deferred.py check --text "<тема и ключевые понятия>"`; хуки UserPromptSubmit
  и SessionStart напоминают об отложенных решениях сами, эта команда — страховка.
- Получил НАПОМИНАНИЕ об отложенном решении — сначала спроси автора, потом работай;
  реестр веди по скиллу `deferred-decisions`.
