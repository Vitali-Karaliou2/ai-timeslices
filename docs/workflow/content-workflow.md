# Работа над содержанием: от логической страницы до приложения

Зафиксировано по промпту автора 11.v1-to-2.prompt (2026-10-27). Изменения процесса —
по решению автора.

## Единица работы — логическая страница
Курс → тематические срезы → **логические страницы** (overview, idea, math, demo, …;
типы — docs/spec/content-schema.md) → физические веб-страницы в приложении.
Одна логическая страница может занять одну или несколько физических; как именно
делить и что закреплять на экране — решается при загрузке
(предложение: ADR 0005, после согласия автора).

## Цикл
1. **Обсуждение среза.** Закончив срез, обсуждаем следующий: какие в нём будут
   логические страницы и в каком порядке. Фиксируем первую и начинаем работу над ней.
2. **Проверка отложенных решений.** Перед первой версией страницы:
   `python3 scripts/deferred.py check --text "<тема страницы, ключевые понятия>"`.
   Если что-то нашлось — сначала вопрос автору (скилл deferred-decisions).
3. **Версия страницы.** Claude присылает `.docx`: текст страницы, затем разделы
   с пометкой «не часть страницы». Обычный такой раздел — **«Решения, откладываемые
   на будущее»**; иногда — вопросы, на которые нужен ответ до следующей версии.
   Тексты страницы помечены `ЧЕРНОВИК:`, сомнительные факты — `ПРОВЕРИТЬ ДАТУ`
   (CLAUDE.md); перед отправкой — субагент fact-reviewer.
4. **Ответ автора** — файл-промпт с правками к версии. Claude отвечает следующей
   версией. Шаги 3–4 повторяются.
5. **Утверждение.** Автор пишет: «Последнюю версию текущей логической страницы можно
   загружать в приложение». Claude в ответ даёт промпт для сессии загрузки
   (шаблон ниже).
6. **Подготовка к загрузке** (в том же чате, где шла работа над страницей): утверждённый
   текст — в `docs/content-sources/<S><P>/<S><P>.v<N>.<English_name>.md` (дословно,
   без разделов «не часть страницы»), рядом — рисунки и их генератор; план сессии —
   в `docs/plans/`. Так сессия загрузки не зависит от файлов проекта на Claude.ai.
7. **Сессия загрузки** (Claude Code, GitHub): страница переносится в `content/`
   (Markdown, рисунки, при необходимости — несколько физических страниц),
   решения из раздела «Решения, откладываемые на будущее» вносятся в
   `docs/deferred/deferred.json`, `pytest` зелёный, PR.

## Имена файлов
`<S><P>.v<N>.<English_name>.docx` — версия N логической страницы P среза S;
`<S><P>.v<N>-to-<N+1>.prompt.docx` — ответ автора на версию N.
- `S` и `P` — по одному символу: `1`–`9`, дальше `A`, `B`, `C`, … (заглавная латиница;
  при сортировке имён цифры идут раньше букв, порядок сохраняется).
- Содержательная часть имени — по-английски, слова через `_`; не транслит.
- Пример: `11.v1.About_this_course.docx` → `11.v1-to-2.prompt.docx` →
  `11.v2.About_this_course.docx`.
- Хранение и размещение файлов — на стороне автора (папка в проекте на Claude.ai).

## Структура .docx версии
1. Текст логической страницы (то, что увидит обучаемый), с рисунками.
2. Разделы «(не часть страницы)», в конце документа:
   - «Решения, откладываемые на будущее» — каждое: вопрос, где возникло, что уже
     известно, к какой будущей теме относится (ключевые слова для реестра);
   - вопросы автору, нужные до следующей версии или до загрузки;
   - прочее служебное (сверенные даты, расхождения с источниками).
При загрузке разделы «не часть страницы» в `content/` не попадают.

## Шаблон промпта сессии загрузки
```
Сессия NN_ИИ, проект ai-timeslices.
Прочитай CLAUDE.md, docs/workflow/content-workflow.md, docs/decisions/ и docs/deferred/deferred.json.
Работай в ветке session-NN-ai-load-<S><P>-<english-name>.
Задача: загрузить в приложение утверждённую логическую страницу <S><P>.v<N>.<English_name>.docx
(источник: docs/content-sources/<S><P>/; план: docs/plans/session-NN-<тема>.md).
1. Текст страницы — в content/slices/<slice-id>/pages/ (Markdown; рисунки — рядом), разделы «не часть страницы» не переносить.
2. Деление на физические страницы и закреплённые рисунки — по ADR 0005 (если он accepted; иначе — одной страницей и спросить).
3. «Решения, откладываемые на будущее» — в docs/deferred/deferred.json по скиллу deferred-decisions (сверь с уже имеющимися записями, без дублей).
4. pytest зелёный; code-reviewer и fact-reviewer; отчёт по скиллу session-report; PR.
Дополнительно в этой сессии: <ничего | …>.
```
