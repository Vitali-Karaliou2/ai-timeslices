# 0006. Заголовки групп, подписи рисунков и ссылка на рисунок в тексте
Дата: 2026-10-27. Статус: accepted (утверждён автором 2026-10-27).

## Контекст
ADR 0005 ввёл `pages[].group` и `pages[].pinned`, но не сказал, откуда берутся заголовок
группы в оглавлении («О чём этот курс») и подпись закреплённого рисунка, и как текст
страницы ссылается на рисунок среза. План сессии 02_ИИ поручил выбрать способ ссылки,
при котором Markdown-файл не знает URL оболочки.

## Решение
- `slice.json.groups`: `{ "<group-id>": { "title": "..." } }` — заголовок логической
  страницы; каждая группа из `pages[].group` обязана быть описана, каждая описанная —
  использована.
- `slice.json.figures`: `{ "<file>": { "caption": "..." } }` — подпись рисунка из
  `figures/`; одна на рисунок, показывается и у рисунка в тексте, и у закреплённого.
  Для закреплённого рисунка подпись обязательна.
- Рисунок в тексте — обычная Markdown-картинка `![Рисунок 1](figures/<file>)`; оболочка
  при рендеринге переписывает путь на `/content/slices/<id>/figures/<file>` и оформляет
  картинку отдельным абзацем как `<figure>` с подписью из `figures`.
- Рисунки лежат в `figures/` плоско; имя — `[A-Za-z0-9][A-Za-z0-9._-]*`.

## Последствия (включая то, что стало труднее)
+ Подпись хранится в одном месте — не расходится между страницами.
+ Markdown-файл переносим: путь относительный, URL оболочки в нём нет.
− Подпись рисунка в тексте не видна в самом Markdown-файле — её надо искать в slice.json.
− Два новых необязательных поля slice.json (схема содержания расширена).

## Альтернативы, которые отвергнуты, и почему
- Подпись курсивным абзацем в тексте страницы (как в источнике) — для закреплённого
  рисунка её всё равно пришлось бы дублировать в манифесте.
- Отдельный `figures/figures.json` — маршрут рисунков отдавал бы и его наружу
  (манифесты не отдаются, ADR 0004); лишний тип файла для валидатора.
- Особая директива `[[figure: …]]` вместо Markdown-картинки — нестандартно, файл хуже
  читается вне оболочки.
- Заголовок группы — из front-matter первой страницы группы: неявно, легко потерять при
  перестановке страниц.
