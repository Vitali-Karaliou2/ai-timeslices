# 0003. СУБД: SQLite + SQLAlchemy + встроенный read-only инспектор /admin/db
Дата: 2026-10-26. Статус: proposed (утверждает автор).

## Контекст
Автору нужна лёгкая навигация по БД «как в Object Explorer MS SQL Server»: видеть все
таблицы и их содержимое. SQLite в предыдущем проекте был обоснован, но неудобен
для изучения структуры. Рассматривались: PostgreSQL + pgAdmin; SQLite + внешние
инструменты (DB Browser for SQLite, Datasette); SQLite + инспектор в самой оболочке.

## Решение
Оставить SQLite (файл `app.db`), доступ только через SQLAlchemy, миграции — Alembic.
Навигацию дать тремя слоями:
1. страница `/admin/db` в самой оболочке — список таблиц, строки (limit 200), DDL;
   работает одинаково локально и в облачной сессии, ничего не надо ставить;
2. локально — DB Browser for SQLite (бесплатный GUI, прямой аналог Object Explorer);
3. при желании — `datasette app.db` (web-UI одной командой; пакет ставится отдельно
   и в requirements.txt не входит).

## Последствия
+ Нулевое администрирование; БД — один файл; инспектор доступен из любой среды.
+ Благодаря SQLAlchemy/Alembic подмена СУБД (например, на PostgreSQL + pgAdmin) —
  это замена строки подключения и прогон миграций, а не переписывание кода.
  «Сначала удобная для навигации, потом другая» не требуется: удобная навигация
  достигается поверх SQLite.
− /admin/db — ещё один кусок кода оболочки, который надо поддерживать (сознательно
  минимальный: reflection, никакого ввода SQL, read-only).

## Альтернативы
PostgreSQL с самого начала — отвергнуто на 0→1: сервер БД в каждой облачной сессии
и локально — лишняя подвижная часть без выгоды при текущих объёмах данных.
