# 0004. Статика содержания: оболочка отдаёт наружу только папки демо доступного среза
Дата: 2026-10-26. Статус: proposed (утверждает автор).

## Контекст
shell-spec описывает `GET /content/...` как «статику содержания (демо, трассы)». Первая
реализация монтировала всю папку `content/` через StaticFiles. Ревью (code-reviewer,
сессия 01) показало, что так страницы недоступного среза читаются напрямую
(`/content/slices/<id>/pages/01-idea.md` → 200), в обход правила «прямой переход
по URL не открывает содержание» (docs/acceptance.md, п. 3).

## Решение
Вместо StaticFiles — маршрут `GET /content/slices/{slice_id}/demos/{path}`: отдаёт файлы
только из `demos/` среза (index.html, player.js, trace.json, gen/…), с проверкой выхода
за папку, и только если срез не Unavailable для текущего пользователя (иначе 403, как
у страниц). Страницы, slice.json, course.json, questions.json и assignments.json наружу
не отдаются — оболочка показывает их через свои шаблоны.

## Последствия (включая то, что стало труднее)
+ Правило линейного порядка нельзя обойти через статику.
+ Код генератора (gen/) по-прежнему доступен iframe-плееру и шаблону страницы демо.
− Демо внутри iframe может ссылаться только на файлы своей папки `demos/<id>/`
  (общие ресурсы между демо — копией или будущим отдельным маршрутом).
− Открыть демо по URL «снаружи» можно только с cookie-сессией (автовход dev-пользователя
  в Development это обеспечивает).

## Альтернативы, которые отвергнуты, и почему
Монтировать всю `content/` — отвергнуто: утечка содержания недоступных срезов.
Монтировать `content/slices/*/demos` без проверки состояния среза — отвергнуто: демо
тоже содержание среза, правило доступа должно быть одним.
