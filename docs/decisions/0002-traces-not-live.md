# 0002. Демо проигрывают заранее насчитанные трассы, а не «живое» обучение
Дата: 2026-10-26. Статус: proposed (утверждает автор).

## Контекст
Ключевой визуальный приём курса — анимация обучения на плоскости: точки по одной
становятся непрозрачными, разделяющая линия двигается по мере обработки примеров.
Её можно реализовать (а) переобучая сеть в браузере на JS, (б) запуская обучение
на бэкенде по запросу, (в) проигрывая заранее насчитанную трассу.

## Решение
На 0→1 — вариант (в): генератор на NumPy/PyTorch пишет trace.json; плеер (чистый
canvas+JS) его проигрывает. Код генератора — одновременно «код для показа» на страницах.

## Последствия
+ Показ детерминирован и воспроизводим (seed); код для показа и исполняемый код — один.
+ Плеер тривиален и един для всех демо; нет дублирования сети на JS (это нарушало бы
  линию «весь код курса — Python/NumPy/PyTorch»).
+ Прямая преемственность с «кадрами и стоп-кадрами» предыдущего проекта: трасса — это
  процесс, шаг — кадр.
− Задания «поменяй параметр и посмотри» требуют перегенерации трассы. На 0→1 обучаемый
  делает это запуском `gen/.../train.py` (это само по себе учит работе с кодом);
  позже возможен live-режим: POST-эндпоинт оболочки, который запускает генератор
  с параметрами пользователя и возвращает свежую трассу (персептроны обучаются за
  доли секунды). Live-режим — отдельный ADR, когда дойдём до заданий.

## Альтернативы
(а) обучение на JS в браузере — отвергнуто: второй код, расходящийся с показываемым
Python-кодом. (б) живой бэкенд с самого начала — отложено: усложняет оболочку
(очереди, таймауты, произвольные параметры) до того, как появилось содержание.
