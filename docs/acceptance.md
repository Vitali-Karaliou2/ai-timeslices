# Приёмочные критерии оболочки, стадия 0→1

Каждое утверждение должен уметь проверить посторонний человек без помощи автора,
за 15 минут, на свежем клоне репозитория. Утверждение, которое нельзя так проверить,
в этот список не попадает.

1. `bash scripts/setup_env.sh` (или `pip install -r requirements.txt`) и `pytest`
   проходят на свежем клоне в облачной сессии и на локальной машине с Python 3.11+;
   тестов не меньше пяти, и они покрывают пункты 3–6.
2. После `uvicorn app.main:app` по адресу `/` открывается карта курса: срезы в линейном
   порядке, с состояниями для dev-пользователя; golden- и winter-периоды различимы.
3. Срез, у которого не пройден предыдущий, показан как «недоступен», и прямой переход
   по его URL не открывает содержание.
4. Внутри среза работает навигация по страницам (вперёд/назад/оглавление); Markdown
   рендерится; «Срез пройден» на последней странице переводит срез в Done и делает
   доступным следующий.
5. Повторное открытие пройденного среза не ломает состояния последующих срезов.
6. Страница демо показывает работающий плеер в iframe из статической папки демо:
   пуск/пауза/шаг/сброс; точки становятся непрозрачными по ходу трассы; рядом виден
   код генератора. `python3 gen/numpy/train.py` перегенерирует `trace.json`
   воспроизводимо (одинаковый seed → одинаковая трасса).
7. Добавление нового среза — это добавление папки в `content/slices/` и строки
   в `course.json` без изменения кода оболочки; `validate_content.py` проходит;
   срез появляется на карте после перезапуска.
8. `/admin/db` показывает все таблицы БД и их строки (read-only).
